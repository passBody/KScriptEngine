## 1. 项目概述

### 1.1 定位

**KScript 是一个用 PyQt5 桌面 GUI 编排"自动操作脚本"的步骤化工具**：把一段段可复用的原子操作（"步骤"）组装成可执行的"步骤列表"，整体打包为 `.kscp` 工程文件（ZIP 归档）保存与分发。

- **解决什么问题**：从示例数据（列表名「打开软件」「清理体力」「检查体力」、变量「莫拉数量」「原石数量」）可推断，需求源头是大量重复性按键/鼠标操作（游戏日常、重复性桌面操作等）。KScript 让**不写代码的人**通过 GUI 编辑步骤卡片来编排操作序列，而不是手写 Python 脚本。
- **工程形态**：纯本地单机应用，无网络/服务端概念。入口 `main.py` → 打开 `.kscp` 工程 → 左侧活动栏 4 棵管理树（步骤列表/变量/步骤模板/资源）+ 中央预览区 + 底部日志面板。

### 1.2 当前状态

- **已成型**：完整的数据模型层、四棵管理树 UI、步骤卡片/列表视图、变量编辑、资源管理、日志系统、图片标注工具、应用图标。
- **已闭环（2026-08-30）**：**步骤执行器（运行时引擎）已实现**——`StepRunner` 工作线程按序执行全部 enabled 步骤（PC+偏移循环、协作式停止、步数上限防死循环），`HotkeyListener` 全局热键驱动待命/启动/停止，配套按键/鼠标点击/输出日志三个步骤模板与执行器 UI（执行按钮/状态栏/编辑锁定/热键设置）。产品已从"编辑器"成为可"运行"的工具。

### 3.2 核心概念模型

```
                        ┌──────────────── .kscp 工程包 (ZIP) ────────────────┐
  StepManager ──动态导入──> actions/**/*.py（步骤模板类，随包分发）            │
        │                        ▲                                          │
        │  create_step / from_format_string                                  │
        ▼                        │                                          ▼
   Step 对象（model/step.py）              step_list.json ──> StepListStore ──> StepList ──> Step
        │  io / status / enabled / do()            (组+列表嵌套字典)   (有序 Step 列表)
        ▼
   StepIOWidget（输入槽存 "{{变量名}}"/常量，输出槽存变量名）
        │  resolve_inputs / write_outputs / picker / gen_widget
        ▼
   variables.json ──> VariableTree ──> ProjectVariable (string / number / image)
        │                                     │
        └── image 类型引用 ───────────────────> assets/ 资源文件 ── ResourceTreeWidget

   LogModel（单例）<── 所有模型错误/操作 ── 贯穿全部层，LogWidget 展示于底部
```

要点：

- **`.kscp` 是唯一工程载体**：含 ① `actions/**/*.py`（步骤模板源码）② `step_list.json`（列表名 → 步骤 base64 串数组）③ `variables.json`（变量树）④ `assets/`（资源）。`KscpPackage` 只做字节存取，**刻意不解析包内 JSON**。
- **Step 是执行单元**：`do()` 编排 input→run→output，返回**偏移量**（1=下一个、2=跳一个、0=重调用自身），由执行器消费（2026-08-30 已实现）；`enabled` 参与过滤。
- **格式串是步骤的序列化协议**：UTF-8 JSON → urlsafe base64 去填充。步骤跨列表复制粘贴、跨工程打包全靠它。
- **名字存在字典键上**：StepList 自身无名字，名字在 StepListStore 的键上；StepIOWidget 不继承 QWidget，是纯数据对象。

### 3.3 数据流

- **打开**：`KscpPackage.from_kscp` → `VariableTree.from_json(variables.json)` + `StepManager.load()`（动态导入包内 actions/*.py）+ `StepListStore.from_json(step_list.json)` → UI 编辑。
- **保存**：各模型 `to_json_bytes()` → `pkg.write_file` → `pkg.save()`（mkstemp + os.replace **原子写盘**）。
- **执行（2026-08-30 已实现）**：`StepRunner.start()` 在工作线程按插入序 DFS 整合全部 enabled 步骤的 do 逐条调用（PC+偏移，负值回跳钳 0）；`HotkeyListener` 全局热键 → 待命/启动/`request_stop()` 协作式停止，GUI 经 Qt 信号跨线程桥刷新。

### 3.4 序列化协议栈

| 层 | 格式 | 细节 |
|---|---|---|
| 工程包 | ZIP（ZIP_DEFLATED） | 条目按名排序保证确定性；目录以 `/` 结尾（空目录靠它存活）；原子写入 |
| 包内 JSON | UTF-8（ensure_ascii=False） | `variables.json` 嵌套字典；`step_list.json` 组+列表字典 |
| 对象格式串 | urlsafe base64（去 `=` 填充） | ProjectVariable：`{"t","d"}`；Step：`{"name","in","out","io","run","tag"}`（缺 run/tag 向后兼容默认）；io：`{"it","iv","ot","ov"}` |

### 4.5 合成卡片（composite-card）——参数签名（纯局部作用域）

- **定义 + 三段签名**：一张合成卡片 = 一个命名可复用 `StepList` + 一个 `CompositeSignature`。签名分输入/输出/局部三段、互不兼任；输入/输出每项用 `Param`（名+类型）、局部每项用 `LocalVar`（名+类型+默认值）；`validate()` 保证段内/跨段不重名。
- **调用点 io 绑定**：body 步骤的输入槽绑定 `{{全局}}`/常量、输出槽指向局部/全局目标；`StepIOWidget.picker` 换成 `make_composite_local_picker` 局部选择器（按**严格类型**列出签名参数、末项「新建局部变量…」快速建局部，纯局部作用域、无全局树回退）。
- **编辑期校验（纯局部感知）**：`_apply_local_picker`/`refresh_error_marks` 把 body 步骤 `io._tree` 换为 `build_validation_tree(sig, package)`（inputs/locals/outputs **全预填**类型默认、无全局回退，区别于运行期 `build_local_tree` 的 inputs 不预填）→ 绑 `{{全局}}` 时 `is_valid` 判 False → 卡片**即时红卡**，与运行期局部树缺失该名 → `resolve_inputs` 抛 `FileNotFoundError` → ERROR 一致（修「编辑期不红、运行期才红」的不一致）；参数less（空签名）body 走全局树（同 v1，运行期不换树）。
- **预览装配**：`CompositeManagementTree.preview_widget()` 返回一个**容器**（上 = 「编辑签名…」按钮、下 = `StepListHost`）；按钮文本显示参数数（`N 入 / N 出 / N 局`），点开弹 `CompositeSignatureDialog`——三段表整合于一弹窗、可增删行（`+`/`−`）+ 重命名（单元格编辑）、**右下角「确定」生效**（取代预览栏内联签名表，避免竖状堆叠拥挤）；弹窗内「名」列经 `_CenteredTextDelegate` + `QTableWidgetItem.setTextAlignment` 「显示+编辑均居中」、「类型」列 `QComboBox` 经可编辑只读 line edit 居中（禁手输防非法类型串）。`composite_tree_widget.py` 对 v2 未改动。
- **自递归防护（exclude_ref）**：编辑卡片 A 时，宿主 `set_list(body, mgr, exclude_ref=A)` 令模板选择器排除 A（防直接/间接递归）。`_on_selected` 与 `_on_store_changed` **两处**都传 `exclude_ref=self._current`——后者补齐是修「新建卡片后能加自身、点其它再点回才不能」：创建新卡 → `refresh` 选中新卡 → `_on_selected` 设正确 `exclude_ref`，但紧随的 `store_changed` → `_on_store_changed` 曾漏传 → 顶掉正确值 → 选择器又列出新卡。
- **签名变更传播（双向调用点重同步）**：B 的签名变更（`_on_signature_changed`）须刷新**所有引用 B 的调用点 io**，分两路互补——① 步骤列表里的调用点：`on_sig_changed_cb` → `main_widget._on_composite_sig_changed` → `StepListManagementTree.resync_composite_steps(ref)`（遍历 `StepListStore`）；② 合成卡片体内的调用点（composite→composite，如 A 的 body 调用 B）：`_resync_bodies_for_ref(ref)`（遍历 `CompositeCardStore` 体内、对 ref 匹配的 `CompositeCard` 步骤调 `resync_io` 按新签名重建类型化 io + 保留旧值）。`resync_io` 把 `io._tree` 设全局树，故随后 `refresh_error_marks` 重设为所属卡片校验树（编辑期正确作用域，否则绑 A 的参数在全局树找不到 → 误红）。② 是修「A 调 B、改 B 签名后 A 内调用点 io 不刷新」。
- **运行期流程**：`input()` 经 `build_local_tree(sig, package)` 建一棵局部 `VariableTree`（locals 填默认值、outputs 填类型默认空、inputs 由入参 `set` 进来）；`run()` 把 body 步骤的 `io._tree` 换成局部树（`try/finally` 恢复原树）并走 mini pc+偏移循环；`output()` 读局部出参写回调用点绑定的全局目标。body 引用不在局部树的名字 → `FileNotFoundError` → 步骤 ERROR（同普通步骤）。
- **存储**：定义存于 `composites.json`（`CompositeCardStore`）；`tree` 为「路径 → 格式串数组/组」的嵌套字典，签名**旁挂于平铺 `sigs` 表**：

```json
{
  "tree": {
    "登录流程": ["<base64 步骤格式串>", "@合成卡片:组/子卡片", "..."],
    "战斗": { "起手": ["<base64 步骤格式串>", "..."] }
  },
  "sigs": {
    "登录流程": {
      "in":  [{"name": "x", "type": "number"}],
      "out": [{"name": "y", "type": "number"}],
      "loc": [{"name": "t", "type": "number", "default": 0}]
    }
  }
}
```

步骤列表里对合成卡片的引用存成轻量标记——带参为 `@合成卡片:<ref>:<io_b64>`（含 io 绑定值），
参数 less（空签名）为裸 `@合成卡片:<ref>`（无 `:io` 段），`from_marker` 按签名建类型化 io 并从
`io_b64` 回填绑定值；签名漂移（标记内 slot 数与签名不符）→ 按签名长度**截取/补空**，多余项置空 →
红卡可定位、不崩。v1 无参、v2 带参，构造器 `(ref, tree, package, signature=None, io=None, enabled=True, tag="")` 向后兼容。

```
# 带参：ref 后接 :<io_b64>（io_b64 = StepIOWidget.to_format_string() 编码的调用点绑定值，
#       base64 串内含 in/out 槽的类型与值，如 iv/ov 记调用点入参常量与「{{全局}}」/出参目标）
@合成卡片:加倍卡:<io_b64>
# 参数 less（空签名）：裸 ref，无 :io 段
@合成卡片:组/卡片A
```

## 6. 代码质量评估

### 6.1 优点（值得保留的设计）

- **异常即契约**：ValueError=非法输入、FileExistsError=冲突、FileNotFoundError=缺失，语义全项目一致。
- **事务性操作**：`insert_format_strings` 先全部解码成功再统一插入；拖拽移动先验证格式串可还原再删源（修过"拖拽哪个丢哪个"的数据丢失 bug）。
- **原子落盘**：mkstemp + os.replace，失败清理临时文件。
- **向后兼容**：格式串缺 run/tag 键默认补值；`ensure_ascii=False` + 无填充 urlsafe base64 保证输出稳定。
- **错误可定位**：格式串坏条目报「第 N 条」；未注册注解报步骤名/字段名/支持列表。
- **防坑积累**：动态属性避开 Q_PROPERTY、blockSignals+try/finally 重建防 use-after-free、动画 finished 即清理防 RuntimeError、弱引用防自引用环、幽灵 proxy 回归防线——每条坑都有注释 + 冒烟断言记录。
- **Windows 平台差异显式注释**（_read_local 预检、模块名前缀防串包）。
- **冒烟测试真实**：RED 阶段要求真实失败输出，GREEN 要求 EXIT=0 且绝不经过管道（防吞退出码）。
