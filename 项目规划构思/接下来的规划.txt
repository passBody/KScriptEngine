在 @actions\ 中添加一个 `步骤基类`
步骤 是用来执行的 后续会创建步骤列表 点击执行后，每个步骤按顺序执行

步骤基类拥有如下属性：
该步骤的名称： str
描述该步骤的作用： str
描述该步骤状态：未执行|执行中|执行结束|执行错误： Enum
步骤输入/输出设置（数据 + GUI 生成器）： `步骤输入/输出设置（数据 + GUI 生成器）`
输入类：描述自身需要哪些输入参数：Class
输出类：描述自身需要哪些输出参数：Class

拥有如下方法：
信息显示窗口（GUI生成器）：可在步骤列表视图中的卡片里生成自定义窗口
input方法：调用`步骤输入/输出设置（数据 + GUI 生成器）`获取值得函数 将返回值设置到输入类中
run方法：用来执行并修改，返回一个步骤偏移量（默认1即意味着运行下一个步骤，如果返回2则运行之后第二个，如果是0，则重新调用自身）
output方法：将输出类中的数据 设置到`步骤输入/输出设置（数据 + GUI 生成器）`中从而影响全局数据
生成格式化数据（通过【描述该步骤的名称，格式化输入类，格式化输出类，格式化`步骤输入/输出设置（数据 + GUI 生成器）`】编码为base64）
静态方法 通过base64码判断能否返回自身（如步骤名称不对、格式化输入输出类签名不匹配则无法生成返回 None， 反之返回自身）

do方法：整合整个流程 返回值是run的返回值 执行顺序如下：
    ① input  # 从`步骤输入/输出设置（数据 + GUI 生成器）`获取输入数据并写入自身输入类中
    ② offset= run  # 调用并可修改输出类
    ③ ouput  # 将输出类中的数据传入`步骤输入/输出设置（数据 + GUI 生成器）`中修改全局变量
    ④ return offset

举例一个步骤
后续可生成一个子类到 @actions/控制流程/time_delay.py
'''
名称：延时
描述：用于延时（单位s）
输入类：
	number

	pass

	判断时间是否大于0，不满足则 切换状态`执行错误` 接着日志报错
	延时number秒
'''

在 @model\ 中添加 步骤列表模型 纯数据模型
其内部保存一个列表 列表中的对象是 步骤对象
拥有如下方法：
1.导出可运行的步骤（通过步骤中的属性判断）的do方法导出为一个大的列表（提供给其他接口用于调用）
2.将自身导出为base格式化的能力（目前已有将每个步骤给格式化的能力）
3.静态方法 将base格式转化为自身
4.静态方法 创建一个空列表
5.添加插入删除移动步骤的能力

在 @model\ 中添加 总步骤列表模型 纯数据模型
用于管理创建的所有 步骤列表模型
拥有如下方法：
1.导出为json的能力
2.静态方法：从json生成数据模型
3.拥有将所有列表中可运行的步骤（通过步骤中的属性判断）的do方法导出为一个大的列表（提供给其他接口用于调用）
    如 列表1 列表2 ... 列表n  ->  解析每个列表所有的do方法并整合为[列表1-do1,列表1-do2,列表1-do3, ... , 列表n-don]
4.添加组的能力
5.在组中添加 步骤列表 的能力

文件内部保存为
step_list.json
{
    打开软件：【步骤列表(格式化)】,
    清理体力：{
            检查体力：【步骤列表（格式化）】,
            ...
        },
    ...
}
其中每个步骤列表都是包含n个步骤对象的列表
